Part 1: Training a Single-Step Denoising UNet

In this part, I built a simple one-step denoiser using a UNet architecture. The goal was to train a model that can denoise images corrupted with Gaussian noise.

The denoising objective is: L = Ez,x ||Dθ(z) - x||²

Where z = x + σε with ε ~ N(0, I)

1.1 UNet Architecture

I implemented a UNet with the following components:

  • Conv blocks: Convolutional layers that preserve spatial dimensions
  • DownConv blocks: Downsampling layers that reduce resolution by 2x
  • UpConv blocks: Upsampling layers that increase resolution by 2x
  • Skip connections: Connecting encoder and decoder layers
  • Hidden dimension D = 128

1.2.3 Denoising Pure Noise

I trained the denoiser to denoise pure Gaussian noise (ε ~ N(0, I)) into recognizable digits.

Observations: When the denoiser is trained to map pure Gaussian noise to clean MNIST images, the input contains no information about which digit the model should produce. Under an MSE loss, the optimal solution is the output that minimizes the squared distance to all training images simultaneously. This is the pixelwise average (centroid) of the dataset. As a result, the model quickly collapses to generating the same blurry, prototype-like digit regardless of the noise input: initially just faint blobs, and after more training, a smooth blend of common MNIST shapes (resembling a fuzzy 0, 3, or 8). These outputs do not represent true samples but rather the dataset’s mean, reflecting the fact that without conditioning, denoising becomes a regression-to-the-average problem rather than a generative one. We see this in the training curve plot: training loss doesn’t improve over iterations, and it fluctuates about the pixel wise avg prediction. The denoised images don’t move closer to the original digits over training epochs, the only noticeable difference is that the predictions are slightly less pixelated in epoch 5 compared to epoch 1.

Part 2: Training a Flow Matching Model

Flow matching enables iterative denoising by learning the velocity field from noise to clean data.

I defined: xt = (1-t)x0 + tx1 where x0 ~ N(0,I) and x1 is clean data

The flow (velocity) is: u(xt, t) = dxt/dt = x1 - x0

Training objective: L = E ||( x1 - x0) - uθ(xt, t)||²

2.1 Time-Conditioned UNet

I extended the UNet to be conditioned on timestep t using FCBlocks (Fully-Connected Blocks):

  • Two FCBlocks to embed scalar t
  • Timestep embedding injected via modulation at unflatten and up1 layers
  • Hidden dimension D = 64

Time Conditioned Unet Architecture

2.3 Sampling from Time-Conditioned UNet

I used iterative denoising using Euler's method with step size Δt. Starting from pure noise, I iteratively predicted and followed the flow to generate clean digits. Notice that even by Epoch 10, it's still difficult to recognise the images as digits.

The time-conditioned UNet struggles to produce recognizable digits because it lacks explicit control over which digit to generate. In flow matching, the model learns a single velocity field that must handle all possible paths from noise to any digit in the dataset. Without class conditioning, when sampling from a random initial noise point, the model doesn't know which of the ten digit classes to flow toward, so the predicted velocity field often points toward an average or interpolated direction between multiple digit modes. This results in the flow trajectory landing in ambiguous regions of the data manifold, producing blurry or inconsistent digits.

2.4 Class-Conditioned UNet

I added class conditioning to control which digit (0-9) to generate:

  • Class c represented as one-hot vector
  • Two additional FCBlocks for class embedding
  • 10% unconditional training (puncond = 0.1) for classifier-free guidance
  • Modulation: unflatten = c1 * unflatten + t1 and up1 = c2 * up1 + t2

2.5 Training the Class-Conditioned UNet

Training Setup:

  • Same as time-conditioned, plus class one-hot vector
  • 10% dropout of class conditioning during training
  • Epochs: 10 (faster convergence with class conditioning)

2.6 Sampling with Classifier-Free Guidance

I used classifier-free guidance with γ = 5.0 to improve sample quality:

ucfg = γuθ(xt, t, c) + (1-γ)uθ(xt, t, ∅)

I generated 4 instances of each digit (0-9)

Class conditioning dramatically improves the quality because it allows the model to learn separate, class-specific velocity fields. By providing the target digit class as a one-hot vector, the flow matching model can predict velocities that specifically guide the trajectory from noise toward the correct digit class in the data distribution. This transforms the single ambiguous velocity field into ten distinct, well-defined flows, one for each digit. The classifier-free guidance further strengthens this by computing a weighted combination of the conditional and unconditional velocity predictions, which steers the flow more directly toward the target class and away from the average of all classes.

2.6 Bonus: Training Without Learning Rate Scheduler

Approach: Just remove the learning rate schedule and keep the learning rate at 1e-2

Performance: Simply removing the learning rate schedule and keeping the learning rate at 1e-2 did not change the quality of the results that much. Performance is slightly worse, see how the digit '4' is fragmented in Epoch 5. Note: I decided to stop training after Epoch 5 for this since the training loss has already converged.

My Guess Why: Removing the learning rate scheduler leads to slightly worse performance because the model trains with a constant high learning rate of 1e-2 throughout all epochs. Early in training, this high learning rate helps the model quickly learn the overall structure of the velocity field and make rapid progress. However, later in training when the model needs to refine the learned flow to accurately predict velocities for smooth trajectories, the high learning rate causes the weights to overstep and oscillate rather than converging to a precise solution. This prevents the flow field from becoming as smooth and accurate as it would be with a decaying learning rate.

Approach: Remove learning rate scheduler and decrease learning rate to 1e-3

Performance:

My Guess Why:Using a smaller fixed learning rate of 1e-3 recovers most of the performance because it enables stable convergence throughout training without requiring a scheduler. While the model learns the velocity field more slowly in early epochs compared to starting at 1e-2, it avoids the instability and oscillations in later training that prevent the flow from being accurately refined. The final performance is similar because by the end of training with a scheduler, the learning rate would have decayed to around 1e-3 anyway, meaning both approaches ultimately train with similar step sizes during the critical later epochs where the flow field is being fine-tuned for accurate sampling.
